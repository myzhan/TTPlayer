# Swift → Qt 复刻差异审查与接手清单（第一轮，历史记录）

> 本文保留 2026-11-19 当日的实现和结论。文中配图对照指向 [Swift 基线截图](https://github.com/myzhan/TTPlayer/tree/c66a60a42e7e809167419fe493d90a2d91d87f25/docs/screenshots)。后续采用 Qt 深色样式；当前实现与复测结果见[修复记录](review-fixes.md)。

审查日期：2026-11-19。基线：`c66a60a` 的 Swift 原版，加当前 working tree 的 Qt 实现（`src/`、`CMakeLists.txt`、跨平台 FFmpeg 脚本尚未入库）。目标是保留原版用户可观察的功能、交互和数据，而不只是做出能播放的相似窗口。

**结论：当前 Qt 版具备基础播放器骨架，但尚不能称为 1:1 复刻。最需要先修的是列表数据边界、现场恢复、元数据链路、切页错误和音频线程设计；继续堆窗口不能解决这些问题。**

本文只做 review，不修改产品代码。不要据此重写 Swift 版；它是行为参考和回归用例来源。Qt 的设备输出可以使用 SDL，不要求照搬 AVAudioEngine，但音频行为必须等价。

## 3. P0：先修数据和核心操作

### R01：左栏切页信号使用了旧项（源码确认）

位置：`src/ui/PlaylistWindow.cpp:138`，`currentItemChanged` 的 lambda 丢弃第一个参数、使用第二个 `cur`。

第二个参数是 previous。首次选择 previous 为空直接返回；从 A 点 B 实际调用 `showPage(A)`，左栏高亮与表格内容错位。新建歌单等直接调用 `showPage` 的路径可能掩盖这个问题，因此模型探针不会发现。

任务：使用 current；统一程序化切页与鼠标选择；`showPage` 必须同步左栏选择而不递归触发。

验收：建内容不同的 A/B/C，连续切页至少 30 次，每次高亮、标题、内容、删除/导出目标一致；包含首次打开和重启恢复。

### R02：浏览页/搜索结果被当作主列表存盘（源码确认）

位置：`MainWindow::saveState`、`restoreLibrary`、`Collections::setAllTracks` / `tracksOf`。

`saveState()` 用 `m_controller->tracks()` 写 `trackPaths`，但这个数组会被切页和搜索替换。保存时若在收藏/某张歌单/搜索态，重启后这部分内容会被 `setAllTracks()` 当成“全部”。`loadDirOrFiles()` 每次打开又直接覆盖全部；`rescanLibrary()` 同样覆盖全部。用户手工添加的歌、电台、扫描内容没有独立归属。

任务：按 Swift 的默认列表、只读媒体库、派生历史页、收藏、歌单、电台页分离数据源；控制器展示数组不能成为全局存档真相。导入是按原版语义添加到目标列表，不能用“打开即替换全部”代替。

验收：默认 A/B、库 C/D、歌单只含 A；搜索 A 或停在收藏退出，重启后各页仍完整；重扫/移除库目录不清掉默认列表和电台。搜索状态触发收藏等即时保存也要验证。

### R03：现场恢复与自动续播没有实现（源码确认）

参考：`Sources/TTPlayer/Models/ResumeScene.swift`、`SceneSuite.swift`。Qt：`LibraryStore::Loaded`、`MainWindow::restoreLibrary`、`m_autoResumePlay`。

Qt 没有恢复当前曲、段内时间、暂停状态、基础上下文、待播队列来路、游标和播放历史的流程。`autoResumePlay` 虽然能勾选并持久化，但没有执行自动续播的消费路径。

任务：移植 resume 数据协议和恢复状态机，区分“恢复现场但停住”与“用户启用自动续播”；保留 `Basic/Next/Later` 来源，旧档宽容恢复。预取必须在本曲真正排入输出之后。

验收：普通文件/CUE/归档分别在非零位置暂停退出；重启恢复同一段的真实 PCM；开启自动续播后才开声；待播的 Next/Later 及随机历史恢复正确，不被搜索页/当前浏览页覆盖。

### R04：CUE 与归档身份往返不完整（源码确认）

位置：`MainWindow::saveState` / `restoreLibrary`、`Collections::trackForKey`、`PlaylistM3U::toIdentityKey`。

- 保存 `t.url()` 丢掉 CUE 的 sheet/track/start/end；恢复成普通镜像文件。多段可能变成多条相同的整盘。
- `trackForKey` 对带 fragment 的 URL 先返回 `Track(u)`，没有解析 `#track=` 并恢复分轨；普通路径 fallback 也只是尽力退成镜像，不能作为等价恢复。
- 归档 `file://…#archive-entry=…` 经 M3U 导入时转成本地路径加 fragment，与 Track 使用的 URL 身份键不一致。
- 重启探元数据对归档调用 `Decoder::openFile(外层包)`，没有走条目 AVIO 通路。

任务：建立唯一 entry resolver，导入/歌单/收藏/存档/重定位共用；普通文件、CUE、归档、电台分别解析，不能字符串截断后假装恢复成功。

验收：CUE 第 2 段加入收藏/歌单并重启、M3U 往返后仍播放第 2 段；同一归档两条目不合并、收藏/搜索/重启身份一致；中文、空格、`#`、percent encoding 均覆盖。

### R05：普通音频标题/歌手/专辑没有接入元数据（源码确认）

位置：`Decoder::finishInit`、`MainWindow::loadDirOrFiles` / `restoreLibrary` / `rescanLibrary`、`Track.cpp`。

解码器虽然抓了容器 tags，导入只设置时长、采样率、声道、格式和 ReplayGain；没有把 title/artist/album 写回 Track。码率参数始终传 0。普通文件因此主要按文件名显示，搜索真实歌手/专辑也失效；只有探针合成数据和 CUE 路径设置了部分文本字段。

任务：补齐原版 `MetadataReader.swift` 的语义，合并容器/音频流标签与技术参数；将本地、归档、重启恢复接到同一元数据流程；保留解析失败原因。

验收：ID3/Vorbis/MP4/APEv2 标签素材用与文件名不同的标题；显示、搜索、属性、重启结果一致；真实码率可见，坏文件提示有原因。

### R06：存档“原子写”并非原子替换（源码确认；丢档窗口未注入复现）

位置：`src/models/LibraryStore.cpp` 的 `save()`。

当前先写 `.tmp`，再 `QFile::remove(target)`，最后 `rename`，且不检查 write/remove/rename 结果。删除原档到重命名成功之间存在无档窗口，注释“原子写”不成立。

任务：使用 `QSaveFile` 等可靠替换流程，检查写入和 commit 结果，失败反馈到上层；坏 JSON 不应被静默当空档覆盖。未知键保留已有基础，但不能替代功能迁移。`dockFrame` 与 Swift `dockGeometry` 等键名差异要明确迁移策略。

验收：隔离档注入写入失败/提交失败，旧档仍可读且逐字节保留；旧档缺键/未知键/损坏字段有明确结果；Qt 回归统一尊重测试目录并校验用户档未变。

## 4. P1：音频链路必须补行为与取证

### R07：预开解码器不等于无缝输出（源码确认）

位置：`AudioEngine::callback`、`PlayerController::onTrackFinished` / `schedulePrefetch`。

EOF 后回调给余下缓冲填零，再排队到主线程；主线程收到后才 `loadAndPlay` 换解码器。预取只减少开文件延迟，不能消除这段填零和事件调度间隔。不能因为 `gaplessEnabled()==true` 就判定无缝成功。

任务：将已准备的下一段 PCM/解码任务在音频边界连续消费，按段绑定 CUE 区间和 ReplayGain，UI 通知延后即可；不同采样率需有明确等价策略。

验收：迁移 `GaplessSuite` 的真实 PCM 衔接检查，记录缺帧/重复/零段；普通文件、压缩格式 priming/padding、相邻 CUE、多次暂停恢复、队列改动、不同增益相邻曲都测。不能只记录 position 增长。

### R08：实时音频回调承担阻塞解码/网络读取（源码确认；卡顿/死锁待实测）

位置：`AudioEngine::callback`、`pause` / `stop`、`RadioStreamSource::read`、`PlayerController::openDecoderFor`。

回调持 `m_mutex` 调 `Decoder::read()`，最终可阻塞到网络 condition_variable；UI 的 pause/stop/seek/频谱取样又等待同一把锁。电台开流和 `avformat_find_stream_info` 也从 UI 路径同步执行，无明确的超时/取消出口。另：pause/stop 持引擎锁调用 SDL 暂停，而 play/切设备路径已经专门避开 SDL 等回调与同锁互等；需统一审计。

任务：后台生产 PCM、回调只消费有界缓冲；停止应先使阻塞 IO 可取消，再回收 worker。音频回调不做网络等待/文件开流/同步释放可能 join 的对象。每次装载给 generation，旧 EOF 通知不能推进新曲。

验收：本地服务模拟无响应、慢首包、停流但不断连接、断线；在每种阶段反复 stop/切歌/关闭至少 30 次，超时采 `sample` 栈；报告 UI 延迟与退出耗时，不能只用 dummy 快流判断线程安全。

### R09：电台只实现了最基础的字节流（源码确认）

位置：`src/audio/RadioStream.cpp`：`Icy-MetaData: 0`；`openDecoderFor`；对照 Swift `RadioStream.swift`、`RadioQuality.swift`、`RadioStations.swift`。

缺少 ICY 音频/元数据拆包与正在播放、连接/缓冲/播放/退避/失败状态、2/4/8/8 重连策略、手动重试、缓冲与断流质量统计。当前结束直接汇入普通 EOF 推进，不能表达直播断线。

任务：独立 radio 会话状态机；连接 generation、取消、用户想播状态分别管理；保留 stop 后装载着台但未连接的语义。迁移原版三个过期回调防护，不能把旧重试/旧 playing 写进新会话。

验收：迁移 `LocalRadioStream` 剧本与 `RadioSuite`；ICY 跨包/编码、断线重连、手动重试、停止后的晚回调、本地↔电台淡入淡出均有证据。

### R10：输出设备只按显示名管理，缺乏热插拔与实际输出状态（源码确认）

位置：`AudioEngine::outputDevices` / `setOutputDevice` / `openDevice`；`SettingsWindow::buildOutput`。

代码把 SDL 设备名注释为 CoreAudio UID，但这里只取得显示名，不能据此承诺稳定唯一身份。指定设备失败虽回退默认，`m_outputDevice` 仍保留旧选择；UI 没有完整的“偏好设备/实际设备/降级原因”区分，也未见设备变化事件处理。设备按解码率、固定 float stereo、禁止格式变化打开，需验证不支持该格式的设备行为。

任务：平台适配设备身份与默认设备跟随；热插拔、实际输出反馈、失败回退、无设备恢复；根据设备能力协商并重采样。

验收：按 `DeviceSuite` 测播放/暂停状态切换、拔插、默认设备改变、同名设备、无设备；不仅检查设置字段，需采真实 PCM 和实际设备。

### R11：EQ 前置增益缺失，音量绕过控制器，DSP 并发无保护（源码确认）

参考：Swift `EQPanelController` 的 preampKnob/volumeKnob、`eqPreGain`。Qt：`EqWindow`、`Equalizer`、`AudioEngine::eq()`。

- Qt 没有独立 EQ preamp。ReplayGain preamp 是另一项功能，不能拿它替代。
- EQ 音量旋钮初始固定 0.8，直接写 engine；主窗的 `m_vol`、静音与落盘不会同步，重新打开旋钮也没从引擎取当前值。
- UI 经裸引用修改 EQ 开关/系数，音频线程同时读同一对象，无锁/快照交接；这是数据竞争，听感后果待取证。
- `play()` 先放开输出，控制器随后才设置新曲 RG，需验证首缓冲串用上一曲增益。

任务：音量/静音/前置增益由统一状态入口管理；DSP 参数通过安全快照/命令交接；曲目增益与 PCM 同时生效。

验收：主窗/EQ/重启三方一致，静音不会被旁路；播音时连续拖十段/切预设/切设备，用 sanitizer 与 PCM 检查；增益/RMS/防削波按 `ReplayGainSuite` 取证。

## 5. P1：曲库与列表工作流缺失

### R12：媒体库自动跟踪、扫描管理和失效文件修复缺失

位置：Qt `scanFolders` / `rescanLibrary`；参考 Swift `MediaLibrary.swift`。

Qt 扫描同步执行，递归只收 playableExtensions，没有统一展开 CUE/M3U/归档；手动打开目录又只读一层。没有文件变化监听、扫描进度/取消、代际合并、离线目录保留、无效条目重定位、路径前缀替换和碰撞检测。重扫覆盖全部的问题见 R02。

验收：迁移 `LibrarySuite`；嵌套目录、盘上增删、扫描中取消/移除根目录、外置盘离线/回来、同名重定位与引用同步更新；在大库扫描时窗口可操作。

### R13：最近播放/最近电台、轨目编辑及电台管理没有接上

Qt `Collections::viewList` 只列收藏、自建、全部；`LibraryStore::Loaded` 未消费 `recentKeys`、`recentRadioKeys`、`trackEdits`、`radioAliases`、`radioCategories`、`radioAssignments`。

任务：恢复独立历史页、去重和顺序；移植 `TrackEdits` 对应的用户编辑流程；电台添加入口、地址归一化、自定义台名、分类 CRUD/移动、改地址时重写各引用、重试与清空黑名单语义。预置台虽然首次有台名，重启 `restoreLibrary` 却用普通 `Track(url)`，需补回统一台名兜底。

验收：逐项复用 `PlaylistSuite` / `UserListSuite` / `RadioSuite`；删除预置台后不回来、改地址后旧身份不复种、台名不伪造 aliases、不抢用户续播现场。

### R14：搜索只有模型命中，用户工作流不完整

位置：`PlaylistWindow::applySearch` / `clearSearch` / `removeRow`，`PlaylistView::paintEvent`。

缺少格式筛选入口、命中来源页显示、搜索前选择和滚动位置恢复。Esc 注释声称退出搜索，但未见对应键盘事件/shortcut 接线。搜索结果删除直接按原先 `viewId` 删除，且立即退出搜索，没有完整定义“命中来自其他页时到底删除哪儿”。新建/修改歌单后索引失效也要沿 UI 路径验证，不能只测模型。

### R16：歌词匹配和 CUE 时间轴不等价（源码确认）
